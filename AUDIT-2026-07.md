# Lumi Derm — Full Production-Readiness Audit

_Deep audit of the public website + admin, backend, security, SEO, and operations._

## Verdict

The platform is **close to production-ready and already usable in the real world**. The public site is complete and polished, the admin is genuinely powerful, and the security posture is above average for a small-clinic site. Nothing here is a "the site is broken" blocker. What remains is a focused list of **operational hardening and a few correctness gaps** that separate "live and working" from "fully production-grade and safe to walk away from."

Overall grade: **B+ / near-production.** Close the P0 list below and it's an solid A.

## 2. Must-do before "fully production ready" (P0)

1. **Verify every production secret/var is set.** Confirm on Cloudflare: `RESEND_API_KEY`, `UNSUB_SECRET`, `GITHUB_TOKEN`, `ADMIN_EMAILS`, `ADMIN_OWNER_EMAILS`/`ADMIN_EDITOR_EMAILS`, R2 `MEDIA` binding, D1 binding, `SITE_ORIGIN`/`FROM_EMAIL`/`REPLY_TO`. (Add `GOOGLE_PLACES_API_KEY` + `GOOGLE_PLACE_ID` when ready.) A single missing secret silently degrades a feature.
2. **Email authentication (SPF, DKIM, DMARC).** Verify these DNS records exist for the sending domain in Resend. Without them, campaigns land in spam and can hurt domain reputation. This is the highest-impact, easiest-to-miss item.
3. **Subscriber data backup / portability.** D1 has automatic Time Travel (~30-day point-in-time restore) and the admin can export confirmed subscribers to CSV — but there's no *scheduled* offsite export. For GDPR resilience, set a routine (e.g. monthly CSV export kept securely, or a scheduled D1 export).
4. **Change the admin soft passcode default.** It's currently `"lumiderm"` in code. Cloudflare Access is the real gate, so this is low-risk, but set a real passcode (Settings → passcode) and don't ship the default.
5. **Decide the Google Reviews timeline.** Feature is built and dormant. Once the API key lands, set the two values and test the import.

## 3. Bugs / not-quite-right (P1)

1. **CSP blocks the Cloudflare Access re-login redirect.** `connect-src` in `_headers` doesn't include your Access team domain (`*.cloudflareaccess.com`). When an admin's Access session expires, background API calls redirect there and throw a confusing CSP console error instead of a clean "please sign in again." Add the Access domain to `connect-src` (ideally scoped to `/admin`), or detect the 302 and prompt re-login.
2. **CI deploys after only a syntax check.** The deploy workflow runs `check:js` but not `npm test` or lint. A change that passes syntax but fails a test would still deploy. Add `npm run check` (tests + site check) as a required step before `wrangler deploy`.
3. **Sitemap `lastmod` dates are stale** and aren't regenerated when content is published. Run `npm run sitemap` in CI (or on publish) so search engines see fresh dates.
4. **Public `/api/subscribe` has a honeypot but no rate limiting** (reviews got IP rate limiting; subscribe didn't). Add the same IP/hour cap to blunt signup spam.
5. **Duplicate migration number `0006`** (`0006_preferences_campaign_tracking.sql` and `0006_review_submissions.sql`). Both applied fine, so it's cosmetic now — but rename future migrations strictly sequentially (0012+) and never reuse a number, or a future `migrations apply` could behave unexpectedly.
6. **Verify the reviews modal on mobile** after the recent layout fixes (two-column → single column at narrow widths, scroll, tap targets).

## 4. Improvements & enhancements (P2 / nice-to-have)

- **Review rich snippets (SEO):** add `Review` / `AggregateRating` JSON-LD so the 5.0 stars can show in Google search results. High marketing value, low effort.
- **SEO controls expansion:** per-page titles/meta (currently homepage only), editable opening hours + legal snippets via the same marker pattern.
- **Email opens tracking:** analytics currently covers clicks, not opens (opens need a tracking pixel — a deliberate privacy/design choice; add only if wanted).
- **Full Google review history:** current Places API returns ~5 recent reviews; the OAuth Business Profile API returns all. Wire up if you want the complete archive.
- **Formal accessibility + Lighthouse pass:** spot checks look good (alt text present, no inline handlers, reduced-motion handling), but run axe/Lighthouse for a documented score (focus traps, ARIA on star inputs, contrast).
- **Performance:** Lighthouse pass; check hero video weight and LCP; confirm image lazy-loading.
- **Monitoring & deliverability:** error tracking (Cloudflare logs/Sentry), uptime check, and Resend bounce/complaint monitoring so a deliverability problem is caught early.
- **Admin mobile:** confirm the admin is usable on a phone/tablet (the clinic owner may use it on the go).
- **Docs housekeeping:** ~8 status/plan docs at the repo root (`IMPLEMENTATION_STATUS`, `PROJECT_COMPLETION_AUDIT`, `CODEX_IMPLEMENTATION_PLAN`, `MANUAL_ACTIONS_REQUIRED`, `PLATFORM_AUDIT_REPORT`, etc.) are stale. Archive into `/docs` and keep one current runbook + `ROADMAP.md`.
- **Test coverage:** expand automated tests to cover worker routes, preference enforcement, review merge/dedupe, and analytics aggregation (several were verified ad-hoc during development, not in the suite).
- **Deploy path clarity:** confirm there's a single source of truth for deploys (the GitHub Action `wrangler deploy`) and document a rollback (git revert + redeploy).

## 5. Security & compliance summary

**Strong already:** CSP, HSTS, X-Frame-Options, Permissions-Policy, `nosniff`, Cloudflare Access on `/admin/*`, server-side RBAC, audit logging, GitHub token kept off the browser, honeypots, review rate limiting, double opt-in consent, ICO-compliance documentation, R2 path sanitisation, anti-open-redirect on tracked links.

**To close:** connect-src Access domain (P1-1), subscribe rate limit (P1-4), scheduled data backup (P0-3), admin passcode default (P0-4), email auth records (P0-2), and a light secret-rotation note for the GitHub/Resend tokens.
